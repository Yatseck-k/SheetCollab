# Правила выполнения задачи

## Входные данные

Перед планированием полностью прочитать `work/TASK.md`, `work/diff.txt` и этот файл.
Если обязательный файл отсутствует или задача не заполнена, сообщить об этом пользователю до реализации.
Пустой `diff.txt` означает, что контекст существующих изменений не предоставлен.

## Планирование и согласование

1. Соблюдать корневой `AGENTS.md` и ограничения проекта из `CLAUDE.md`.
2. Изучить код, необходимый для конкретного плана.
3. Заполнить `work/PLAN.md`: перечислить подтверждённые файлы, изменения, проверки, риски и критерии завершения.
4. Кратко представить план пользователю и дождаться явного одобрения перед реализацией.
5. При существенном изменении плана обновить его и повторно согласовать.

## Реализация

- Выполнять только согласованный объём задачи; не добавлять попутный рефакторинг.
- Сохранять существующие пользовательские изменения; не отменять их без указания пользователя.
- Все HTTP-вызовы ActiveCollab выполнять только через `app/Repositories/ActiveCollab/ActiveCollabRepository.php`.
- Не раскрывать токены, содержимое `.env` и другие секреты в diff, логах, ответах API или исключениях.
- Оставлять контроллеры тонкими: валидация → DTO → сервис; бизнес-логику размещать в сервисах.
- Сохранять формат `external_id`: `{spreadsheet_id}:{sheet_id}:{row_number}`; поле — неуникальный локатор позиции. UUID-интеграции идентифицировать по `(integration_id, record_uuid)`, без усыновления связи по номеру строки. Переносить только контролируемой командой с аудитом при остановленной записи.

## Проверка и отчёт

- Выполнить проверки из согласованного плана; перед PR запустить `make test`.
- Сообщить о причине проблемы, изменённых файлах, результате исправления, проверках и оставшихся рисках или непроверенных сценариях.
- Если проверка недоступна, прямо указать причину; не выдавать её за успешную.
